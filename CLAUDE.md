This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Windows-only desktop app that auto-records work hours (출퇴근/업무시간). It runs as a system-tray app that starts on login, logs clock-in, pauses counting on screen lock / screensaver / 3-minute idle, resumes on return, and records clock-out on shutdown (with heartbeat-based recovery for hard power-offs). Korean is the UI language.

## Running & commands

There is **no build, lint, or test framework**. It is plain Python 3.13 + standard library + three packages (`pywin32`, `pystray`, `pillow`).

- **`python` on this machine is the Microsoft Store stub and does not execute code — always use the `py` launcher.** Real interpreter: `C:\Users\chaa8\AppData\Local\Programs\Python\Python313-32\` (`python.exe` / `pythonw.exe`).
- Install deps + register autostart + launch: double-click `setup.bat` (or `py -m pip install -r requirements.txt`).
- Run the tray app windowless: `pythonw time_tracker.pyw` (full path to `pythonw.exe` if not on PATH — it usually isn't).
- GUI dashboard standalone: `py dashboard.py`. Text report: `py report.py [--date YYYY-MM-DD]`.
- Autostart: `py install_autostart.py [--status|--remove]` (writes `HKCU\...\Run`, no admin needed).

### Manual smoke testing (the established pattern)

Data lives at `%LOCALAPPDATA%\TimeTracker\time_tracker.db`. To exercise code without polluting real records, **override `LOCALAPPDATA` to a temp dir** for the test process, populate events via `storage.Storage` with explicit timestamps, then run/launch. For GUI checks, launch with `pythonw`, `Start-Sleep`, capture the screen with .NET `System.Drawing` (`CopyFromScreen`), then `Stop-Process`. Always restore `LOCALAPPDATA` and clean the temp dir afterward.

## Architecture

Five cooperating pieces; the non-obvious logic is the **active-interval model** and the **threading model**.

- **`storage.py`** — the source of truth. SQLite `events` table holds `start`/`stop` boundary rows (reason: clock_in/unlock/lock/screensaver/idle/clock_out/shutdown/crash_recovery), plus a `meta` table holding `last_active` (the heartbeat). Work time = sum of paired start→stop intervals. Key behaviors:
  - `intervals()` walks events **by id (insertion = chronological order)**, pairing starts with stops; a still-open trailing interval is extended to `last_active` (so a crashed/running session reports correctly).
  - `recover_unclean_shutdown()` runs at startup: if the last event is a dangling `start`, it inserts a synthetic `stop` at `last_active` — this is how clock-out is recovered after a hard power-off.
  - `seconds_for_day` clips intervals to a date so totals **split correctly across midnight**; `week_range` is Monday–Sunday. `last_event_time()` returns the last event's ts (used to clamp backdated idle stops). Formatting helpers: `fmt_hm` renders `H시간 M분` but **drops zero parts on both ends** — `0분` when under an hour (34분), and a bare `H시간` when the minutes are 0 (8시간, not "8시간 0분") — while `fmt_dur` shows sub-minute spans honestly as `N초` (delegating to `fmt_hm` at ≥60s) so short non-work gaps aren't flattened to "0분". The 0-minute suppression flows through every caller (현황 card, weekly chart's "휴가 8시간", tray tooltip, report).
  - **Work/non-work split + manual correction.** `stay_seconds` = first activity → last activity for a day; `split_for_day(intervals, day, adjust_sec, leave_kind)` returns `(work, nonwork)` holding the invariant **work + nonwork = stay**, clipped to `[0, stay]`. The per-day signed correction has **two stores that are always summed by `total_adjust_seconds(day)`** — that sum, never `get_adjust_seconds` alone, is what every caller passes as `adjust_sec`: (1) the `manual_nonwork` table, one row per chunk added with **＋ 비업무 추가** (`add_manual_nonwork` → key `m<id>`, `manual_nonwork_seconds`, `delete_manual_nonwork`, `reduce_manual_nonwork`, `clear_manual_nonwork`), which exists so an addition **shows up as a row in the 비업무 tab** with its own 사유; and (2) `meta` `adjust:YYYY-MM-DD` seconds (`get/set/add_adjust_seconds`) which now only holds the leftover of **− 비업무 빼기** after `reduce_manual_nonwork` has eaten the newest manual rows first (so subtracting never leaves a phantom row behind). A **positive** total moves time from work into non-work. All callers (dashboard, tray summary, report, export) go through `split_for_day`, so a correction shows up everywhere consistently. An **ongoing pause is reflected live**: `ongoing_pause_now(day)` returns `now` when the last event is a non-work stop (reason in `NONWORK_REASON_LABELS`) started that day; passed as `pause_until`/`until` into `split_for_day`/`stay_seconds`, it extends stay to `now` so 체류/비업무 keep ticking while paused instead of jumping on resume.
  - **Non-work period list + notes.** `nonwork_periods(day)` derives the pause periods (gaps between activity intervals, clipped to the stay bounds, plus a live `ongoing` entry while paused); each period is keyed by the **id of the stop event that opened the gap** (`stop_id`), whose reason gives the method label (`NONWORK_REASON_LABELS`). Manually added chunks are appended to the same list with `stop_id="m<id>"`, `reason=MANUAL_REASON` ("수기 추가"), `manual=True` and **`start`/`end` of `None`** (they have no clock times — every consumer must handle that), and they show up even on a day with no recorded activity. Free-text 사유 notes attach to that key in `meta` under `nwnote:<stop_id>` (`get/set_nonwork_note`) so they survive across days and refreshes; `is_manual_key` tells the two kinds of key apart.
  - **Vacation / business-trip / half-day (휴가/출장/반차).** Stored in `meta` under `leave:YYYY-MM-DD` = `vacation`|`trip`|`halfday` (`get_leave`/`set_leave`, cleared by deleting the row). Two different behaviors in `split_for_day`: a **full** kind (`LEAVE_FULL_KINDS` = vacation/trip) **overrides everything and returns `(LEAVE_DEFAULT_SEC=8h, 0)`** regardless of recorded events; **반차 (`LEAVE_HALF`)** instead runs the normal stay/work/nonwork math and then **adds `LEAVE_HALF_SEC=4h` to work** (the off half-day has no events), so it is the one case where `work + nonwork = stay` deliberately does not hold. `LEAVE_LABELS` maps the keys to Korean.
  - **Deleting a non-work period.** `delete_nonwork_period(stop_id)` routes an `m<id>` key to `delete_manual_nonwork` (drops the row, so the correction shrinks by that much). For a real gap it removes the gap's `stop` event **and the first `start` event after it**, so `intervals()` pairing lets the preceding interval run straight through — the gap is absorbed into work time, stay is unchanged, and non-work drops by the gap. It also deletes the period's `nwnote:` row. Returns `False` for a non-stop/unknown id or for the **ongoing** pause (no resuming `start` to merge with).
  - Connection uses `check_same_thread=False`; writes are serialized by the caller's lock (see below), not by SQLite.
  - **Counting-method settings** live in the same `meta` table under `setting:<key>` keys (`get_settings`/`set_setting`, defaults in `DEFAULT_SETTINGS`): `idle_enabled`, `idle_threshold_sec`, `lock_enabled`, `screensaver_enabled`. Stored as strings, coerced back to bool/int on read. This is the **IPC channel** between the dashboard (which edits them) and the running tray app (which re-reads them each poll).

- **`time_tracker.pyw`** — the tray app. Contains two classes:
  - `Tracker` = the state machine + DB writer. Flags `locked`, `screensaver`, `idle`, `manual_pause` track **physical** state (set regardless of settings); `_effective_pause()` then ANDs each with its `*_enabled` setting (manual pause always counts) so a disabled method never pauses. `_recompute()`/`_apply_locked()` emit a `start` or `stop` only on active↔inactive transitions. `refresh_settings()` reloads settings from the DB and reconciles (toggling a method off mid-pause resumes counting, emitting a `settings_change` boundary). All DB access — including the settings read — is under `self.lock`.
  - `App` = OS integration. Creates a **hidden win32 message window** to receive `WM_WTSSESSION_CHANGE` (lock/unlock via `WTSRegisterSessionNotification`) and `WM_ENDSESSION` (shutdown → clock_out). A background poll loop (`_heartbeat_loop`, every `POLL_SEC`) calls `refresh_settings()`, detects screensaver (`SPI_GETSCREENSAVERRUNNING`) and idle (`GetLastInputInfo` ≥ the **configurable** `idle_threshold_sec`), writes the heartbeat every `HEARTBEAT_SEC`, and refreshes the tray tooltip. **On idle detection the `stop` event is backdated to the last-input time (≈ `now − idle_elapsed`), not the detection time, so the threshold delay isn't counted as work; it's clamped to never precede the previous event's ts (insertion = chronological order).**
  - **Threading model (important):** main thread runs `win32gui.PumpMessages()` (owns the hidden window); the heartbeat poll loop and the `pystray` icon each run on their own daemon threads. Quitting posts `WM_DESTROY` → `PostQuitMessage`.

- **`dashboard.py`** — tkinter GUI (dark theme). A lightweight **tab bar** (`_build_tabs`/`_show_tab`, plain `tk.Label` buttons toggled via `pack`/`pack_forget` — no `ttk.Notebook`, to keep the dark theme) switches between three pre-built frames: **현황** (the dashboard), **비업무** (today's pause periods), and **설정** (counting-method toggles + idle-minutes spinbox + data export). The dashboard is built **once**, then `_refresh()` updates label text and canvas item coords/colors in place every 5 s (no destroy/recreate — that was a deliberate fix for flicker). The settings tab is **edit-gated**: it opens read-only with toggles/stepper disabled and an **편집** button; `_enter_edit` snapshots current values and unlocks the controls (showing **저장**/**취소**); **저장** (`_save_edit`→`_save_settings`) writes all four keys via `set_setting`, **취소** (`_cancel_edit`) restores the snapshot. Nothing persists until 저장, and the tray app picks it up within `POLL_SEC`. The weekly chart shows **weekdays only (월~금, `WEEKDAYS_SHOWN=5`)** — Sat/Sun were dropped from the chart, weekly total, and average (the 오늘 card still reflects today even on a weekend). The chart draws one **dashed vertical 8-hour baseline** (`chart_baseline`, `GRID` colour, created after the bars so it sits on top) whose x is recomputed each `_refresh` from the current scale (`BAR_X0 + BAR_MAX * WORKDAY_SCALE_SEC/scale`). A collapsible **출장 · 휴가 · 반차** panel under the chart has one button per weekday that cycles 근무→출장→휴가→반차 (`_cycle_leave` → `set_leave`); marked days render with the `LEAVE_COLORS` map (`TRIP`/`VAC`/`HALF`) and a "휴가 8시간" / "반차 4시간" label (반차 shows recorded work + 4h, so it grows with the day). Those four states use a **deliberately desaturated palette** (`BAR_WORK`/`BAR_TODAY`/`TRIP`/`VAC`/`HALF`, plus `NW_PAUSE`/`NW_MANUAL` for the 비업무 method labels) kept separate from the bright UI accents `ACCENT`/`TODAY`/`GOOD` — the bars and weekday buttons must not use the accent colours, that was the point of the change. The 현황 tab's today card shows a **비업무** (non-work) cell beside 체류시간 and a **collapsible** manual-correction section (`_build_adjust`): a button-like full-width toggle bar (▼/▲ chevron + 펼치기/접기 label + `HOVER` colour on mouse-over; `_toggle_adjust` packs/forgets `adjust_body`, `_refit_height` resizes the window) that's collapsed by default. Inside, a number stepper + `＋/−/초기화` buttons adjust today's correction: **＋ writes a `manual_nonwork` row** (so it appears in the 비업무 tab), **−** eats the newest manual rows first and only then writes a negative `adjust:` meta, and **초기화** clears both (with a `askyesno` confirm when manual rows exist, since their 사유 go too); all three then call `_refresh()` **and** `_refresh_nonwork()`. `_apply_adjust` **clamps the resulting total correction to `[-base_nonwork, +base_work]`** so non-work can never go below 0 (subtract limit = current non-work) nor work below 0 (add limit = current work) — keeping the displayed correction linked to reality. Both number inputs use the custom **`Stepper`** widget (replaces `tk.Spinbox`, whose tiny arrows + blinking caret were poor UX): `− [entry] +` (small flat buttons), click/focus selects-all, non-blinking caret (`insertofftime=0`) that disappears on commit (Enter / button / focus-out → `_defocus`), `value()` clamps to `[lo, hi]`. The 설정 idle field passes `on_commit=_save_settings` so it persists on commit (not per keystroke); `set_enabled` greys it out when idle detection is off. Each setting's on/off uses a custom **`ToggleSwitch`** (replaces the plain `tk.Checkbutton`): a rounded pill + sliding knob rendered with **Pillow at 4× then LANCZOS-downscaled** (tk Canvas has no anti-aliasing, so a Canvas-drawn circle looked jagged) into a cached `ImageTk.PhotoImage` on a `tk.Label`; muted `TOGGLE_ON/OFF/KNOB` colours (plus dimmed `*_DIS` variants for the disabled/locked state via `set_enabled`). It flips the bound `BooleanVar` only when enabled; a `var` trace re-renders on external changes. Fonts/paddings were tuned down to keep the window short. Window auto-sizes to required content via `winfo_reqwidth/reqheight` so labels are never clipped regardless of font/DPI, but height is **clamped to `screenheight − 80`** (both in `__init__` and `_refit_height`) so a long list never runs off-screen. On open, `_apply_dark_titlebar` calls DWM `DwmSetWindowAttribute(hwnd, 20=DWMWA_USE_IMMERSIVE_DARK_MODE, 1)` on the top-level HWND (`GetParent(winfo_id())`, then a withdraw/deiconify to force a repaint) so the titlebar matches the dark theme, and `_set_window_icon` draws the tray icon design (dark circle + clock hands) with Pillow into an `ImageTk.PhotoImage` kept on `self` for `iconphoto`; both are wrapped in try/except (Windows-only, fail silently). The **비업무 tab** (`_build_nonwork`/`_refresh_nonwork`) lists the `nonwork_periods` of the currently-viewed day (`self._nw_day`, default today) one grid row each — method label (colored per reason), `start → end` ("진행 중" while ongoing, **"—" for a 수기 추가 row, which has no times**), duration via `fmt_dur` (sub-minute shows as `N초`, never "0분"), an editable 사유 `Entry` saved to `nwnote:<stop_id>` on Enter/focus-out, and a **삭제** button (`_nw_del_btn` → `_delete_nw`, `WARN` colour on hover) that confirms via `messagebox.askyesno` and calls `delete_nonwork_period` — the ongoing row gets no button since it can't be merged. After a successful delete the row's `stop_id` is popped from every tracking dict **before** refreshing (otherwise `_flush_nw_notes` would re-write the note that was just deleted), `_nw_sig` is cleared to force a rebuild, and both `_refresh_nonwork()` and `_refresh()` run so 현황's 비업무/실 업무 update immediately. The header has **◀/▶ date navigation** (`_nw_shift`, reusing the `_adj_btn` style): ▶ clamps at today and is disabled (`disabledforeground=SUB`) when already on today, and a small **오늘** button (`_nw_goto_today`, pack/forget) appears only on past days. The list lives in a **scroll area** (`nw_canvas` + inner `nw_list` frame via `create_window`): `_on_nw_frame_configure` sizes the canvas to `min(content, NW_LIST_MAX_H≈9 rows)` and only then shows the dark **ttk `Scrollbar`** (`clam` theme, `NW.*` style — the native win theme ignores colours) and enables the wheel; `<MouseWheel>` is bound via `bind_all`/`unbind_all` only while the cursor is over the canvas. Rows are **rebuilt only when the period signature `(day, (stop_id, ongoing)…)` changes** (day included so switching dates rebuilds); otherwise time/duration labels update in place every tick so the ongoing row counts up live without stealing focus from a note being typed (`_flush_nw_notes` saves pending text before any rebuild). Empty 사유 fields show a **placeholder** "사유 입력…" in `SUB` (flag-tracked per `stop_id` in `nw_placeholder`; cleared on FocusIn, restored on empty FocusOut) — `_nw_note_text` treats a placeholder-active row as empty string in both save paths so the placeholder **never persists as data**. Saving flashes **"사유 저장됨"** (GOOD, `after(2000)` clear) only when the value actually changed (compared against `nw_saved[stop_id]`, seeded with the loaded note) so routine focus-out/rebuild flushes stay silent. Korean IME composition font in those entries is forced to match via `set_ime_composition_font` (imm32), re-applied on FocusIn/Key because Tk resets it. The 설정 tab also carries a **데이터 내보내기 card**: ◀ YYYY-MM ▶ month picker (future months disabled), output folder persisted in `meta` `export_dir` (위치 변경 → folder dialog), 내보내기 → `export.export_month`. Launched by the tray menu via `subprocess.Popen([sys.executable, ...])` (sys.executable is pythonw → no console).

- **`report.py`** — CLI/text equivalent of the dashboard, used as a fallback. Reconfigures stdout to UTF-8 so Korean survives any console codepage.

- **`export.py`** — CSV export (`daily_/weekly_/nonwork_<tag>.csv`), shared by the dashboard's 내보내기 button and a CLI (`py export.py [--month YYYY-MM | --from/--to]`). Writes **UTF-8 BOM (`utf-8-sig`)** so Excel opens Korean correctly. Skips Sat/Sun and days with no records and no leave mark; nonwork detail minutes are floored at 1 (`max(1, round(sec/60))`) so listed periods never export as 0분.

## Windows-specific gotchas (learned the hard way)

- **`.bat` files must be ASCII-only.** Korean text in a batch file misparses under the Korean console codepage (949) — some UTF-8 bytes look like `|`/`&` and split `echo` lines into bogus commands. Keep batch messages in English; let Python handle Korean output.
- `pythonw`/`python` are frequently **not on PATH**; resolve the real path via the `py` launcher (`py -c "import sys,os; print(os.path.join(os.path.dirname(sys.executable),'pythonw.exe'))"`) — `setup.bat` does this.
- The DB intentionally lives in `%LOCALAPPDATA%`, **not** the repo dir, to avoid OneDrive sync conflicts (the working tree is inside a OneDrive folder).
