# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Windows-only desktop app that auto-records work hours (출퇴근/업무시간). It runs as a system-tray app that starts on login, logs clock-in, pauses counting on screen lock / screensaver / 3-minute idle, resumes on return, and records clock-out on shutdown (with heartbeat-based recovery for hard power-offs). Korean is the UI language.

## Running & commands

There is **no build, lint, or test framework**. It is plain Python 3.13 + standard library + three packages (`pywin32`, `pystray`, `pillow`).

- **`python` on this machine is the Microsoft Store stub and does not execute code — always use the `py` launcher.** Real interpreter: `C:\Users\chaa8\AppData\Local\Programs\Python\Python313-32\` (`python.exe` / `pythonw.exe`).
- Install deps + register autostart + launch: double-click `setup.bat` (or `py -m pip install -r requirements.txt`).
- Run the tray app windowless: `pythonw time_tracker.pyw` (full path to `pythonw.exe` if not on PATH — it usually isn't).
- GUI dashboard standalone: `py dashboard.py`. Text report: `py report.py [--date YYYY-MM-DD]`.
- Autostart: `py install_autostart.py [--status|--remove]` (writes `HKCU\...\Run`, no admin needed).

### Manual smoke testing (the established pattern)

Data lives at `%LOCALAPPDATA%\TimeTracker\time_tracker.db`. To exercise code without polluting real records, **override `LOCALAPPDATA` to a temp dir** for the test process, populate events via `storage.Storage` with explicit timestamps, then run/launch. For GUI checks, launch with `pythonw`, `Start-Sleep`, capture the screen with .NET `System.Drawing` (`CopyFromScreen`), then `Stop-Process`. Always restore `LOCALAPPDATA` and clean the temp dir afterward.

## Architecture

Five cooperating pieces; the non-obvious logic is the **active-interval model** and the **threading model**.

- **`storage.py`** — the source of truth. SQLite `events` table holds `start`/`stop` boundary rows (reason: clock_in/unlock/lock/screensaver/idle/clock_out/shutdown/crash_recovery), plus a `meta` table holding `last_active` (the heartbeat). Work time = sum of paired start→stop intervals. Key behaviors:
  - `intervals()` walks events **by id (insertion = chronological order)**, pairing starts with stops; a still-open trailing interval is extended to `last_active` (so a crashed/running session reports correctly).
  - `recover_unclean_shutdown()` runs at startup: if the last event is a dangling `start`, it inserts a synthetic `stop` at `last_active` — this is how clock-out is recovered after a hard power-off.
  - `seconds_for_day` clips intervals to a date so totals **split correctly across midnight**; `week_range` is Monday–Sunday. `last_event_time()` returns the last event's ts (used to clamp backdated idle stops). Formatting helpers: `fmt_hm` renders `H시간 M분` but **drops zero parts on both ends** — `0분` when under an hour (34분), and a bare `H시간` when the minutes are 0 (8시간, not "8시간 0분") — while `fmt_dur` shows sub-minute spans honestly as `N초` (delegating to `fmt_hm` at ≥60s) so short non-work gaps aren't flattened to "0분". The 0-minute suppression flows through every caller (현황 card, weekly chart's "휴가 8시간", tray tooltip, report).
  - **Work/non-work split + manual correction.** `stay_seconds` = first activity → last activity for a day; `split_for_day(intervals, day, adjust_sec, leave_kind)` returns `(work, nonwork)` holding the invariant **work + nonwork = stay**, clipped to `[0, stay]`. The per-day signed correction has **two stores that are always summed by `total_adjust_seconds(day)`** — that sum, never `get_adjust_seconds` alone, is what every caller passes as `adjust_sec`: (1) the `manual_nonwork` table, one row per chunk added with **＋ 비업무 추가** (`add_manual_nonwork` → key `m<id>`, `manual_nonwork_seconds`, `delete_manual_nonwork`, `reduce_manual_nonwork`, `clear_manual_nonwork`), which exists so an addition **shows up as a row in the 비업무 tab** with its own 사유; and (2) `meta` `adjust:YYYY-MM-DD` seconds (`get/set/add_adjust_seconds`) which now only holds the leftover of **− 비업무 빼기** after `reduce_manual_nonwork` has eaten the newest manual rows first (so subtracting never leaves a phantom row behind). A **positive** total moves time from work into non-work. All callers (dashboard, tray summary, report, export) go through `split_for_day`, so a correction shows up everywhere consistently. An **ongoing pause is reflected live**: `ongoing_pause_now(day)` returns `now` when the last event is a non-work stop (reason in `NONWORK_REASON_LABELS`) started that day; passed as `pause_until`/`until` into `split_for_day`/`stay_seconds`, it extends stay to `now` so 체류/비업무 keep ticking while paused instead of jumping on resume.
  - **Non-work period list + notes.** `nonwork_periods(day)` derives the pause periods (gaps between activity intervals, clipped to the stay bounds, plus a live `ongoing` entry while paused); each period is keyed by the **id of the stop event that opened the gap** (`stop_id`), whose reason gives the method label (`NONWORK_REASON_LABELS`). Manually added chunks are appended to the same list with `stop_id="m<id>"`, `reason=MANUAL_REASON` ("수기 추가"), `manual=True` and **`start`/`end` of `None`** (they have no clock times — every consumer must handle that), and they show up even on a day with no recorded activity. Free-text 사유 notes attach to that key in `meta` under `nwnote:<stop_id>` (`get/set_nonwork_note`) so they survive across days and refreshes; `is_manual_key` tells the two kinds of key apart. `add_manual_nonwork(day, sec, note="")` writes that note for the new row in one go — that is how a picked 사유 태그 becomes the row's 사유.
  - **사유 태그.** The pick-list behind the 비업무 tab's ＋ button is one `meta` row, `nonwork_tags`, holding the tags newline-separated in user order (`get/set/add/remove_nonwork_tag`; `set_nonwork_tags` de-duplicates, drops blanks and truncates each to `TAG_MAX_LEN`=12). An **unset** row means "never touched" → `DEFAULT_NONWORK_TAGS` (식사/휴식/외출/개인용무/회의); an **empty string** means the user deleted them all → empty list. Tags are just text: deleting one never touches 사유 already written into `nwnote:` rows.
  - **Vacation / business-trip / half-day (휴가/출장/반차).** Stored in `meta` under `leave:YYYY-MM-DD` = `vacation`|`trip`|`halfday` (`get_leave`/`set_leave`, cleared by deleting the row). Two different behaviors in `split_for_day`: a **full** kind (`LEAVE_FULL_KINDS` = vacation/trip) **overrides everything and returns `(LEAVE_DEFAULT_SEC=8h, 0)`** regardless of recorded events; **반차 (`LEAVE_HALF`)** instead runs the normal stay/work/nonwork math and then **adds `LEAVE_HALF_SEC=4h` to work** (the off half-day has no events), so it is the one case where `work + nonwork = stay` deliberately does not hold. `LEAVE_LABELS` maps the keys to Korean.
  - **Deleting a non-work period.** `delete_nonwork_period(stop_id)` routes an `m<id>` key to `delete_manual_nonwork` (drops the row, so the correction shrinks by that much). For a real gap it removes the gap's `stop` event **and the first `start` event after it**, so `intervals()` pairing lets the preceding interval run straight through — the gap is absorbed into work time, stay is unchanged, and non-work drops by the gap. It also deletes the period's `nwnote:` row. Returns `False` for a non-stop/unknown id or for the **ongoing** pause (no resuming `start` to merge with).
  - Connection uses `check_same_thread=False`; writes are serialized by the caller's lock (see below), not by SQLite. Because the dashboard is a **separate process** reopening the same file every 5 s, the connection also sets **WAL + `synchronous=NORMAL` + `timeout`/`busy_timeout` = `DB_TIMEOUT_SEC` (15 s)** — a `database is locked` raised in the tray app's poll thread used to be fatal to it (see `_heartbeat_loop`). The PRAGMAs are wrapped in try/except so a filesystem that refuses WAL still works.
  - **Settings** live in the same `meta` table under `setting:<key>` keys (`get_settings`/`set_setting`, defaults in `DEFAULT_SETTINGS`): `idle_enabled`, `idle_threshold_sec`, `lock_enabled`, `screensaver_enabled`, `goal_alarm_enabled`, `goal_sec`. Stored as strings, coerced back to bool/int on read. This is the **IPC channel** between the dashboard (which edits them) and the running tray app (which re-reads them each poll).
  - **Daily-goal alarm state.** The target is the `goal_sec` setting (`DAILY_GOAL_SEC` = 8 h is only its default); `goal_notified(day)`/`set_goal_notified(day)`/`clear_goal_notified()` store **one** `meta` row (`GOAL_NOTIFIED_KEY` = the last notified date, not one row per day) so the popup fires at most once a day and re-arms automatically when the date rolls over — or immediately when the dashboard saves a changed `goal_sec`, which clears the row so the new target can fire today.

- **`time_tracker.pyw`** — the tray app. Contains two classes:
  - `Tracker` = the state machine + DB writer. Flags `locked`, `screensaver`, `idle`, `manual_pause` track **physical** state (set regardless of settings); `_effective_pause()` then ANDs each with its `*_enabled` setting (manual pause always counts) so a disabled method never pauses. `_recompute()`/`_apply_locked()` emit a `start` or `stop` only on active↔inactive transitions. `refresh_settings()` reloads settings from the DB and reconciles (toggling a method off mid-pause resumes counting, emitting a `settings_change` boundary). All DB access — including the settings read — is under `self.lock`.
  - `App` = OS integration. Creates a **hidden win32 message window** to receive `WM_WTSSESSION_CHANGE` (lock/unlock via `WTSRegisterSessionNotification`) and `WM_ENDSESSION` (shutdown → clock_out). A background poll loop (`_heartbeat_loop`, every `POLL_SEC`) runs **`_poll_once`**, which calls `refresh_settings()`, detects screensaver (`SPI_GETSCREENSAVERRUNNING`) and idle (`GetLastInputInfo` ≥ the **configurable** `idle_threshold_sec`), writes the heartbeat every `HEARTBEAT_SEC` (10 s), runs `_check_goal()` when `goal_alarm_enabled`, and refreshes the tray tooltip. **The loop wraps each `_poll_once` in try/except and never dies** — an escaping exception used to end the daemon thread silently, freezing the heartbeat and idle/lock detection for the rest of the session while the tray icon stayed alive (the visible symptom was the dashboard's 최근 활동 stuck at one time). Swallowed exceptions go to `log_error()` → `%LOCALAPPDATA%\TimeTracker\tracker_error.log` (there is no console under `pythonw`), and a repeat of the **same** `type: message` is logged only once so a persistent failure can't spam the file (which is also truncated past `ERROR_LOG_MAX_BYTES`). Poll state (`_prev_ss`/`_prev_idle`/`_last_hb`) lives on `App` so it survives a failed iteration. **`_check_goal`** reads the `goal_notified` flag first and bails, so the full `summary()` re-scan stops happening once the alarm has fired for the day; on crossing the `goal_sec` passed in from the loop it sets the flag (both under `tracker.lock`) and calls **`_goal_popup`**, which `subprocess.Popen`s **`notify.py`** (the styled toast, see below) with the worked/goal seconds. If that launch raises it logs and falls back to **`_popup`** — the old `MessageBoxW` (`MB_OK|MB_ICONINFORMATION|MB_SETFOREGROUND|MB_TOPMOST`) **on its own daemon thread**, since the box is modal and would otherwise stall the poll loop until dismissed. **On idle detection the `stop` event is backdated to the last-input time (≈ `now − idle_elapsed`), not the detection time, so the threshold delay isn't counted as work; it's clamped to never precede the previous event's ts (insertion = chronological order).**
  - **Threading model (important):** main thread runs `win32gui.PumpMessages()` (owns the hidden window); the heartbeat poll loop and the `pystray` icon each run on their own daemon threads. Quitting posts `WM_DESTROY` → `PostQuitMessage`.

- **`dashboard.py`** — tkinter GUI (light theme, see **디자인** below). A lightweight **tab bar** (`_build_tabs`/`_show_tab`, `Pill` buttons toggled via `pack`/`pack_forget` — no `ttk.Notebook`, so the theme stays ours; the active tab is `ACCENT_SOFT` fill + `ACCENT_INK` text) switches between three pre-built frames: **현황** (the dashboard), **비업무** (today's pause periods), and **설정** (counting-method toggles + idle-minutes spinbox + an 알림 section holding the goal-alarm toggle + its hours stepper + data export). The dashboard is built **once**, then `_refresh()` updates label text and canvas item coords/colors in place every 5 s (no destroy/recreate — that was a deliberate fix for flicker). The settings tab is **edit-gated**: it opens read-only with toggles/stepper disabled and an **편집** button; `_enter_edit` snapshots current values and unlocks the controls (showing **저장**/**취소**); **저장** (`_save_edit`→`_save_settings`) writes all six keys via `set_setting`, **취소** (`_cancel_edit`) restores the snapshot. The 알림 card sits inside the same edit gate (it is not a counting method, but shares the one 편집 button), so a new setting means touching `_read_settings` defaults, `_enter_edit`'s snapshot, `_cancel_edit`, and `_save_settings` together. Nothing persists until 저장, and the tray app picks it up within `POLL_SEC`. The weekly chart shows **weekdays only (월~금, `WEEKDAYS_SHOWN=5`)** — Sat/Sun were dropped from the chart, weekly total, and average (the 오늘 card still reflects today even on a weekend). The track and the bars are **not Canvas rectangles but `round_img` images** on `create_image` items (Canvas has neither a corner radius nor anti-aliasing), so they get the same slightly-rounded ends as the rest of the UI: one shared track image (`_track_img`, `BAR_MAX×BAR_H`, radius `BAR_R`) and a per-row bar image rebuilt at the new width on every `_refresh`. Two consequences: a Canvas item only stores the image *name*, so the `PhotoImage` must be kept alive in `self._bar_imgs[i]`; and since each bar width is a new cache key, `round_img` clears `_ROUND_CACHE` past `ROUND_CACHE_MAX` (safe — everything on screen holds its own reference). The chart draws one **dashed vertical 8-hour baseline** (`chart_baseline`, `GRID` colour, created after the bars so it sits on top) whose x is recomputed each `_refresh` from the current scale (`BAR_X0 + BAR_MAX * WORKDAY_SCALE_SEC/scale`). A collapsible **출장 · 휴가 · 반차** panel under the chart has one button per weekday that cycles 근무→출장→휴가→반차 (`_cycle_leave` → `set_leave`); marked days render with the `LEAVE_COLORS` map (`TRIP`/`VAC`/`HALF`) and a "휴가 8시간" / "반차 4시간" label (반차 shows recorded work + 4h, so it grows with the day). Bars are `ACCENT` for today / `BAR_WORK` for past days, and a marked day takes `LEAVE_COLORS`; the weekday buttons are `Pill`s that take the matching pastel `LEAVE_SOFT` fill with the `LEAVE_COLORS` tone as text+border. **`_activity_state(last, last_active)`** classifies the recording state as `none`/`active`/`paused`/`ended`/`stale` and drives both the header status label (`_status`) and a small note line under the 최근 활동 cell (`lbl_last_note`, kept at `height=1` so an empty note doesn't change the layout). This exists because **최근 활동 legitimately stops moving** — it is the end of the last activity interval, so during a pause it stays at the pause time while 체류/비업무 keep ticking, which reads as a broken refresh; `paused` now labels it "자리비움 중" (TODAY) and names the reason in the header. **`stale`** = last event is a `start` but `last_active` is older than `STALE_SEC` (120 s, vs. a 10 s heartbeat) — i.e. the tray app is gone or its poll thread died; both the value and the note turn `WARN` ("기록 멈춤 · 트레이 앱 확인"). The 현황 tab's today card shows a **비업무** (non-work) cell beside 체류시간; the manual-correction section (`_build_adjust`) lives at the **top of the 비업무 tab** instead (it used to be a collapsible section on the 현황 card — it is now a plain always-open card built with `_card`, with no toggle bar, since the tab it sits in is already the non-work view). Its header carries the `lbl_adjust` "보정 ＋N분" readout, now updated in `_refresh_nonwork` (not `_refresh`) from `total_adjust_seconds(self._nw_day)`. It **applies to the day the tab is currently showing** (`self._nw_day`, which the ◀/▶ nav moves), not to today, so the buttons always edit the day whose periods are listed below them. Under the buttons sits a **사유 태그 chip row** (`_build_tags`/`_render_tags`/`_tag_chip`): one clickable chip per tag from `get_nonwork_tags()`, at most one selected at a time (`self._nw_tag`, click again to deselect, selected chip = `NW_MANUAL` bg), a trailing **＋** chip that reveals an inline entry (`_toggle_tag_entry`/`_add_tag`, Enter adds, Esc cancels, new tag is auto-selected) and **right-click on a chip deletes the tag** (`_delete_tag`, confirmed; already-written 사유 text is untouched). The selected tag is passed to `add_manual_nonwork(day, sec, note=tag)` so the new 수기 추가 row shows up in the list **with that tag as its 사유** — the point of the tags. The tag entry reuses `self.nw_font` + `_nw_focus_in` for Korean IME composition, which is why the font is created at the top of `_build_nonwork` (before `_build_adjust` runs). A number stepper + **symbol-only `－`/`＋` buttons** (`_sym_btn` — **same box size as the text buttons** `_adj_btn`: only the glyph is bumped to 11 pt bold with `pady` cut to 2 so the height still matches 초기화, plus ACCENT/TODAY colouring to set them apart from the `Stepper`'s own small ±; the wording used to be "− 비업무 빼기"/"＋ 비업무 추가", and a 16 pt version was too big) + `초기화` adjust that day's correction: **＋ writes a `manual_nonwork` row** (so it appears in the 비업무 tab), **−** eats the newest manual rows first and only then writes a negative `adjust:` meta, and **초기화** clears both (with a `askyesno` confirm when manual rows exist, since their 사유 go too); all three then call `_refresh()` **and** `_refresh_nonwork()`. The total correction still has to stay in `[-base_nonwork, +base_work]` (non-work never below 0, work never below 0), but `_apply_adjust` is now **all-or-nothing**: if the requested delta would cross a limit it applies **nothing** and flashes the reason in `lbl_adj_msg` (`_adjust_limit_msg`/`_adj_flash`, WARN, cleared after 4 s). It used to apply the leftover headroom instead, which is why pressing "10분" repeatedly once the limit was near produced rows of `4분`, `10초`, `10분` — partial amounts nobody asked for. Both number inputs use the custom **`Stepper`** widget (replaces `tk.Spinbox`, whose tiny arrows + blinking caret were poor UX): `− [entry] +` (small flat buttons), click/focus selects-all, non-blinking caret (`insertofftime=0`) that disappears on commit (Enter / button / focus-out → `_defocus`), `value()` clamps to `[lo, hi]`. The 설정 idle field passes `on_commit=_save_settings` so it persists on commit (not per keystroke); `set_enabled` greys it out when idle detection is off, and the 목표 시간 stepper mirrors that pairing via `_sync_goal_state` + a `var_goal` trace. Each setting's on/off uses a custom **`ToggleSwitch`** (replaces the plain `tk.Checkbutton`): a rounded pill + sliding knob rendered with **Pillow at 4× then LANCZOS-downscaled** (tk Canvas has no anti-aliasing, so a Canvas-drawn circle looked jagged) into a cached `ImageTk.PhotoImage` on a `tk.Label`; `TOGGLE_ON`(=ACCENT)/`OFF`/`KNOB` colours (plus dimmed `*_DIS` variants for the disabled/locked state via `set_enabled`). It flips the bound `BooleanVar` only when enabled; a `var` trace re-renders on external changes. Fonts/paddings were tuned down to keep the window short. Window auto-sizes to required content via `winfo_reqwidth/reqheight` so labels are never clipped regardless of font/DPI, but height is **clamped to `screenheight − MAX_H_MARGIN`** (titlebar+border+taskbar; both in `__init__` and `_refit_height`) so a long list never runs off-screen, and `_refit_height` **pulls the window up** when the newly-grown window would hang below the taskbar (it grows downward from wherever it was centred, so switching from a short tab to the tall 설정 tab used to push its bottom off-screen). On open, `_apply_dark_titlebar` calls DWM `DwmSetWindowAttribute(hwnd, 20=DWMWA_USE_IMMERSIVE_DARK_MODE, **0**)` on the top-level HWND (`GetParent(winfo_id())`, then a withdraw/deiconify to force a repaint) — the name is historical: it now **forces the titlebar light** so it matches the light body even when Windows itself is in dark mode. `_set_window_icon` draws the tray icon design (teal disc + white clock hands, same as `time_tracker.pyw`'s `_make_image`) with Pillow into an `ImageTk.PhotoImage` kept on `self` for `iconphoto`; both are wrapped in try/except (Windows-only, fail silently). The **비업무 tab** (`_build_nonwork`/`_refresh_nonwork`) lists the `nonwork_periods` of the currently-viewed day (`self._nw_day`, default today) one grid row each — method label (a pastel `Pill` chip; `NW_METHOD_COLORS` maps each reason to a `TAG_COLORS` pair), `start → end` ("진행 중" while ongoing, **"—" for a 수기 추가 row, which has no times**), duration via `fmt_dur` (sub-minute shows as `N초`, never "0분"), an editable 사유 `Entry` saved to `nwnote:<stop_id>` on Enter/focus-out, and a **삭제** button (`_nw_del_btn` → `_delete_nw`, `WARN` colour on hover) that confirms via `messagebox.askyesno` and calls `delete_nonwork_period` — the ongoing row gets no button since it can't be merged. After a successful delete the row's `stop_id` is popped from every tracking dict **before** refreshing (otherwise `_flush_nw_notes` would re-write the note that was just deleted), `_nw_sig` is cleared to force a rebuild, and both `_refresh_nonwork()` and `_refresh()` run so 현황's 비업무/실 업무 update immediately. The header has **◀/▶ date navigation** (`_nw_shift`, reusing the `_adj_btn` style): ▶ clamps at today and is disabled (`disabledforeground=SUB`) when already on today, and a small **오늘** button (`_nw_goto_today`, pack/forget) appears only on past days. The list lives in a **scroll area** (`nw_canvas` + inner `nw_list` frame via `create_window`): `_on_nw_frame_configure` sizes the canvas to `min(content, NW_LIST_MAX_H≈9 rows)` and only then shows the themed **ttk `Scrollbar`** (`clam` theme, `NW.*` style — the native win theme ignores colours) and enables the wheel; `<MouseWheel>` is bound via `bind_all`/`unbind_all` only while the cursor is over the canvas. Rows are **rebuilt only when the period signature `(day, (stop_id, ongoing)…)` changes** (day included so switching dates rebuilds); otherwise time/duration labels update in place every tick so the ongoing row counts up live without stealing focus from a note being typed (`_flush_nw_notes` saves pending text before any rebuild). Empty 사유 fields show a **placeholder** "사유 입력…" in `SUB` (flag-tracked per `stop_id` in `nw_placeholder`; cleared on FocusIn, restored on empty FocusOut) — `_nw_note_text` treats a placeholder-active row as empty string in both save paths so the placeholder **never persists as data**. Saving flashes **"사유 저장됨"** (GOOD, `after(2000)` clear) only when the value actually changed (compared against `nw_saved[stop_id]`, seeded with the loaded note) so routine focus-out/rebuild flushes stay silent. Korean IME composition font in those entries is forced to match via `set_ime_composition_font` (imm32), re-applied on FocusIn/Key because Tk resets it. The 설정 tab also carries a **데이터 내보내기 card**: ◀ YYYY-MM ▶ month picker (future months disabled), output folder persisted in `meta` `export_dir` (위치 변경 → folder dialog), 내보내기 → `export.export_month`. Launched by the tray menu via `subprocess.Popen([sys.executable, ...])` (sys.executable is pythonw → no console).

- **`notify.py`** — the 목표 달성 알림 팝업, a toast styled like the dashboard (it imports `dashboard`'s palette + `Pill`, so a theme change carries over). Run as **its own process** — `pythonw notify.py <worked_sec> <goal_sec>` — because the tray app's main thread is inside `PumpMessages` and its other threads belong to pystray/polling, so there is nowhere to run a Tk loop; a separate process also means a broken popup can't take the tracker down. Borderless (`overrideredirect`) card pinned bottom-right above the taskbar, `-topmost`, alpha fade in/out, auto-closes after `SHOW_MS` (15 s), and click-anywhere/Esc/Enter/확인 to dismiss. Corners are rounded by **DWM** (`DWMWA_WINDOW_CORNER_PREFERENCE`), not by a transparent key colour — the key-colour trick fights the alpha fade (they share the same layered-window attributes) and left pink corner fringes.

- **`report.py`** — CLI/text equivalent of the dashboard, used as a fallback. Reconfigures stdout to UTF-8 so Korean survives any console codepage.

- **`export.py`** — CSV export (`daily_/weekly_/nonwork_<tag>.csv`), shared by the dashboard's 내보내기 button and a CLI (`py export.py [--month YYYY-MM | --from/--to]`). Writes **UTF-8 BOM (`utf-8-sig`)** so Excel opens Korean correctly. Skips Sat/Sun and days with no records and no leave mark; nonwork detail minutes are floored at 1 (`max(1, round(sec/60))`) so listed periods never export as 0분.

## 디자인

The look is **borrowed from the sibling app `../todo_list`** ("주간 업무 보드", Electron) so the two feel like one family. Keep them in sync when either changes.

- **Tone: "유칼립투스 어스톤"** — green-grey neutrals + a teal accent, warnings in clay red / ocher. The constants at the top of `dashboard.py` map 1:1 onto that app's CSS tokens in `renderer/index.html`: `BG`=`--bg` `#EDF0ED`, `CARD`=`--surface`, `CARD2`=`--surface-2`, `LINE`=`--line`, `FG`=`--ink`, `SUB`=`--muted`, `ACCENT`/`ACCENT_SOFT`/`ACCENT_INK`, `WARN`=`--danger`, `TODAY`=`--warn`. `TAG_COLORS` is its 8-colour pastel tag palette (`--t{0-7}b/t`) as (background, text) pairs — used for 사유 태그 chips, 비업무 method chips and the header status chip. **`LEAVE_COLORS`/`LEAVE_SOFT` deliberately spread the hue** instead (근무 teal · 출장 blue · 휴가 amber · 반차 magenta, each with a matching pastel fill for the weekday button): the four states sit next to each other in the chart, and an earlier all-cool set (blue-grey / indigo / plum) was too close to tell apart at a glance.
- **It follows that app's default (light) theme**, chosen because this PC's Windows app theme is light and the Electron app has no stored theme override, so it renders light there too. The tracker itself has **no theme switch** — if the todo app is flipped to dark, this palette block is the one place to change (plus `_apply_dark_titlebar`, which currently forces the titlebar light).
- **Rounded corners come from images, not tk.** tk widgets have no radius/shadow, so `round_img()` renders a rounded rectangle with Pillow (4× supersample → LANCZOS, cached in `_ROUND_CACHE`) and the `Pill` widget (a `tk.Label` subclass) shows it as its background with the text drawn on top via `compound="center"`. Because it subclasses `tk.Label`, `pack`/`grid`/`bind`/`state="disabled"` work like the old `tk.Button`s did; **changing the text must go through `set_text()`/`set_style()`** so the background image is re-measured (a bare `config(text=…)` would keep the old width). Cards, by contrast, are plain frames with `highlightthickness=1` + `highlightbackground=LINE` — square corners, since a card's size changes with content and an image background would have to be redrawn on every resize.
- Buttons: `_adj_btn` = todo's `.btn` (white fill, hairline border, radius 8), `_settings_btn(..., primary=True)` = `.btn.primary` (teal fill, white text), the 삭제 buttons = `.btn.danger-ghost` (no border, muted → clay red on hover).

## Windows-specific gotchas (learned the hard way)

- **`.bat` files must be ASCII-only.** Korean text in a batch file misparses under the Korean console codepage (949) — some UTF-8 bytes look like `|`/`&` and split `echo` lines into bogus commands. Keep batch messages in English; let Python handle Korean output.
- `pythonw`/`python` are frequently **not on PATH**; resolve the real path via the `py` launcher (`py -c "import sys,os; print(os.path.join(os.path.dirname(sys.executable),'pythonw.exe'))"`) — `setup.bat` does this.
- The DB intentionally lives in `%LOCALAPPDATA%`, **not** the repo dir, to avoid OneDrive sync conflicts (the working tree is inside a OneDrive folder).
